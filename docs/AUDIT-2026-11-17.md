## 复核中被改判的三条

- perf-audit：「`ALIVE_EVERY` 让内存每 300 s 采样一次」**错**：它是 300 **ticks**（2.1 s@144 Hz、6–7 s@50 Hz）。真问题是单位漂移，已改秒。
- perf-audit / arch-audit：「复用 out 表有中风险」**下调为低**：`main.lua` 注释自述 OutFrame 读不出来，引擎不写回。
- arch-audit：「`ad_input.M.bound()` 无调用」**错**（`tools/test_integration.lua:172-178` 是测试接缝）；「观测代码在 pcall 外」下调：`ad_async` 的 drain/step 已各自 pcall。

## 缺口（不臆造，也不假装已解决）

1. **运行时无 per-stage p95**：`perf` 默认 off，要开一局才有 `perf_log.txt`。本轮的分配优化因此只做了「按代码结构必然减少分配」的部分，没有前后帧时间对比。
2. ~~**`RegisterHook` / Delayed Actions 的返回值契约**~~ **已结案（2026-11-17 取证）**：`KintaroModding/ue4ss` release 分支的 `docs/lua-api/global-functions/` 与 `UE4SS/src/Mod/LuaMod.cpp` 给出确定答案——`RegisterHook` 返回两个整数 id；`UnregisterHook(path, preId, postId)` 是唯一形式且**不返回值**；注销是延迟移除但 Lua 回调立刻失效；`CancelDelayedAction` 对已结束/已清空的 handle 返回 false；`RegisterKeyBind` 无注销 API；模组卸载时引擎统一清理 hook/keybind/延迟动作。据此修正了代码（见 CHANGELOG 的「取证后的修正」）与四份文档。
3. **Lua 版本权威说明**：现有证据是实机日志（5.4 选项被接受），不是 UE4SS 文档原文。
4. **`NotifyOnNewObject` 是否可用**（4 个晚加载目标的 class path），未验证，因此未接线。
5. **UE4SS Lua 是否有 JSON 库**：`ad_json.lua` 仍是自实现（123 行，有 61 个单测）。
6. **README 的 2,683 与 `wc -l hit_times.txt` 的 2,507**：前者含 `learned_hits.txt` 冷启动补的条目，口径不同；文档改为「约 2,500 条」并把口径写清。
7. **`ad_input.M.tag` 死代码判断**：见 P2-6，保留。
8. **「正常释放」路径仍无断言**：`releaseCheck` 是 chunk-local，测试无法构造 pending 状态，
   现有 3 条只验证「不抛错」。要覆盖得加注入 seam（`_G.__RELEASE_ARM` 或 `tl.releaseCheck`
   测试钩子），本轮未加——加它就是为测试改产品接口，值得单独决定。
9. **6 处 `_C` 剥除未归一化**（`main.lua:778/802/806/2245/2301/3420`）：这些是日志串与查表
   兜底，不是决策主路；主路已全走 `RT.bname`。留着是因为它们服务于「名字写错也要能查到」的
   降级，改成唯一规则会改变落日志的字符串。
10. **`main.lua:107-140` 的内联兼容兜底仍在**：半更新安装（新 main.lua + 旧模块）时这两段
   直接调 5.4 专有/旧模块没有的函数。保留是刻意的降级路径，`ad_compat` 缺失时不会崩。

## 手法与教训（留给下一轮）

- **先让门禁说真话，再谈优化**：这轮最大的收益不是任何单点提速，而是 `selene tools/`、lua5.4 smoke、`check_std`、`check_docs` 让「绿」变成可信的绿。
- **判据不一致比判据错更危险**：两条调度路径一个要求 handle、一个不要求，任何一侧的失败都会被另一侧的「成功」掩盖。
- **测试接缝要先设计**：`tl.decide` 抽出来之前，决策链一条断言都写不了；抽出后 12 条断言当天就位。
- **子代理结论必须复核**：四条结论被改判（一条把 ticks 当秒、一条把测试接缝当死代码、一条高估复用风险、一条高估 pcall 暴露面）。
- **文档里的数字一定会腐烂**：能算的就让脚本算（`check_docs.py`），不能算的（断言数）就不要写进文档。
- **LuaJIT 200-local 上限包含块内 local**：这轮所有新状态都塞进 `RT` 表或块内，靠「不新增顶层 local」保住 chunk 可编译。
- **selene 的文件级抑制是 `--# selene: allow(...)`**：单 `--` 只压制紧随的**一条语句**，
  照着写会以为加了 allow 却仍红（0.31.0 实测，团队里两人踩到）。
- **Lua pattern 不能给捕获组加量词**：`"\(_C\)+$"` 静默永不匹配；剥重复后缀要写成
  `while s:sub(-2) == "_C" do s = s:sub(1, -3) end`。
- **局部函数顺序 = 真 bug 温床**：`RT.rememberHook` 最初写在 `local tl` 之前，里面读 `tl`
  就成了全局查找（运行到 hook 站点直接 nil）。selene 的 `undefined_variable` 是这类错误唯一
  便宜的探针——所以它必须在门禁里。
- **改名要连带改完引用**：`err`→`ret` 后日志行仍读 `err`，selene 在 `main.lua:4298` 当场抓到。
- **测试用 `gaps` 表汇总缺失 seam，末尾 `eq(#gaps, 0)`**：契约没落地时只红一条、且直接点名，
  比让 42 条断言各自崩强得多。
- **PyYAML 会把裸键 `on` 读成布尔 `True`**：校验 workflow 触发条件要 `doc.get("on", doc.get(True))`，
  否则「没有 push 触发」这种结论读不出来。
